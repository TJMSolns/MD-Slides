# MS-030 evidence: relative image paths render (v1.1.2)

- **Defect (found by the MS-028 verifier, 2026-10-21):** `![alt](./images/x.png)` and `images/x.png` were copied to
  `DECK/images/images/x.png` while the HTML referenced `images/x.png`, so the image was missing. Bare names worked.
- **Fix:** the copier and the renderer share one rule, `ImageAssetCopier.outputPath`. A relative path keeps its folders
  under `images/` (`./images/x.png` and `images/x.png` both go to `images/x.png`; `pics/x.png` to `images/pics/x.png`).
  A path outside the deck folder (`../shared/logo.png`, absolute paths) is copied by file name. Per-slide background
  images use the same rule.
- **Tests:** `ImagePathRoundTripSpec` renders real decks and checks that every `src` in the HTML exists on disk, for
  `./images/x.png`, `images/x.png`, a bare name, a nested folder, `../` and an absolute path, plus backgrounds.
